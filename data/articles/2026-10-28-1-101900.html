この記事で分かることは次の通りです。Spacesheepは、AIの出力をそのまま共有できる「スペース」（共有ページ）に変えます。チームでコメントや共同編集、署名をまとめる運用が考えられます。

ざっくり言うと

  • AIが出した文章や画面を、そのままチームで見られる共有ページにする道具です。
  • ページに意見を書いたり、誰かに署名してもらったりできます。
  • はじめは無料で使い始められます。

どんなツールか

Spacesheepは、AIエージェント（指示で作業を進めるAI）の出力を「スペース」（共有ページ）に変えるサービスです。

スペースは、インタラクティブな文書やライブの見せ方、モックアップ、簡単なアプリのように扱えます。

作ったスペースは、特定の人だけ、チームだけ、または公開のいずれかで共有できます。

行単位でコメントを付けられます。共同編集もできます。すべてのバージョンは保存されます。

サービスは spacesheep.dev として提供されています。運営側が用意したホスト型のサーバーとOAuth（ブラウザ承認）で動きます。

開発の一部パーツはMITライセンスで公開されています。npmのパッケージ名は「spacesheep」です。

Spacesheepは「YC F26」としても表記されています。

何ができるか

AIやエージェントが作った内容をそのままスペースにできます。作ったページは人とAIの両方が読み、コメントし、編集できます。

スペースはドキュメント、ダッシュボード、モックアップ、アプリなどの形で扱えます。全ての編集履歴は保存されます。

作成したスペースはGoogle Driveと同期できます。GitHubと同期することもできます。

電子署名機能があります。署名は当事者のメールに送られ、そのメールで名前と日付をページ上に挿入する仕組みです。署名を呼び出すための関数は request_signatures({ uuid, parties: … }) として用意されています。

重要な点として、エージェントが他の人の代わりに署名することはできません（agent can never sign for anyone）。

エージェントやSlack経由、あるいはSpacesheep自身のAIと連携できます。Claude、ChatGPT、Grokといったホスト型アシスタントとは、接続のための追加が必要な場合があります。

公開や同期の操作は、ブラウザ拡張、コマンド操作（CLI：コマンドを打って操作する仕組み）、MCPプラグイン（ホスト型アシスタントに接続する小さな追加機能）などで行えます。

CLI および MCP 上で実行可能な操作例には、deploy、edit、read_space、list_spaces、share_space、add_comment などがあります。

導入の流れ（公開・同期・連携）

ここでは公開や連携を始めるときの流れを、事実に基づいて示します。

既に使っているAIに「use spacesheep.dev …」と依頼すると、AIがスペースを生成して共有する流れがあります。AIがページを作り、指定した相手と共有できます。

ブラウザ経由や対話環境では、npx spacesheep login を実行してブラウザの承認を得ます。承認の完了を最大10分待つ場合があります。

公開はコマンドで行えます。例として npx -y spacesheep@latest deploy ./dist を実行すると、フォルダや.htmlファイルを公開してURLが出力されます。

非対話のサーバーやCI（自動処理環境）では長期キーを使って接続します。長期キーは ss_で始まる形式で、npx -y spacesheep@latest connect ss_… [name] を使って接続します。

CI連携の一例として、GitHub Actionsで SPACESHEEP_KEY をシークレットに入れ、micmmakarov/spacesheep-cli@v1 を使う手順が示されています。

Chrome拡張を使うと、開いているページやファイルを1クリックでSpacesheepに公開できます。2回目のクリックで同じスペースを更新できます。

エージェント側の導入例として、npx -y spacesheep@latest install を実行してマシンをサインインさせる方法があります。複数のマシンには --ssh host1,host2 のようなオプションを使う例があります。

ホスト型アシスタントへ接続するには、まず Claude 等にプラグインを組み込む必要があります。例としては次のようなコマンドが用いられます：claude plugin marketplace add && claude plugin install spacesheep@spacesheep、または claude mcp add --transport http --scope user spacesheep。プラグインを導入した後はセッションを再起動してください。

【想定シナリオ】

以下は架空の人物を想定した使い方の例です。使い方のイメージを示します。こうした場面で使えるという使い方が考えられます。

研修担当のAさんの場合

困っていること：研修資料が点在し、参加者からの修正要望を集めにくい状況です。

使い方の例：AIに研修資料の草案を作らせます。生成された資料をSpacesheepでスペースにします。スペースを研修参加者に共有し、行ごとのコメントで現場の意見を集めるという使い方が考えられます。

期待できること：コメントで集めた指示を基に、AIや編集者が同じページ上で修正し、全ての版を残す運用が考えられます。受講確認が必要なら、電子署名機能で参加者に署名を求める流れが想定できます。

SNS用コンテンツを整理する個人事業主のBさんの場合

困っていること：SNS投稿案や画像のモックアップが散らばり、管理が面倒です。

使い方の例：AIに投稿案やモックアップを作らせます。ブラウザ拡張を使って開いているページを1クリックでSpacesheepに公開します。更新も同じ拡張でワンクリックです。こうした使い方が考えられます。

期待できること：作った素材をGoogle DriveやGitHubと同期して保存できます。チームの協力者がコメントで修正案を出し、共同編集で仕上げる運用が考えられます。

非IT担当のCさん（社内レポートの担当）の場合

困っていること：社内データをまとめた報告書を、関係者と速やかに共有したいが手間がかかる状況です。

使い方の例：AIにデータ要約やレポート案を作らせ、Spacesheepでライブダッシュボード風のスペースを作ります。チームに共有して行ごとのコメントで修正点を集めます。必要に応じてGoogle DriveやGitHubと同期するという使い方が考えられます。

期待できること：ダッシュボードを見ながら意見を出し合い、修正履歴を残して運用できます。署名が必要な場合は電子署名の仕組みで当事者にメールを送り署名を集める流れが想定できます。

似たサービスとの違い・向いている人

特徴は、AIエージェントの出力を直接スペースにして、そのまま共有・編集・バージョン管理できる点です。

署名のワークフローが組み込まれている点も特徴です。署名は当事者がメールで行い、エージェントが代行することはできません。

公開や同期の手段が多様です。Chrome拡張、CLI、MCPプラグインなどからページを公開・更新できます。

向いている人は、AIの出力をチームで共有し、コメントや版管理、署名を一元化したい担当者です。

よくある疑問

  • スペースはどこに保存できますか？

    作成したスペースはGoogle DriveまたはGitHubと同期できます。

  • 署名は自動で済ませられますか？

    署名は当事者のメールで行います。エージェントが代理で署名することはできません。

  • 公開や更新はどのように行えますか？

    ブラウザ拡張で1クリック公開や更新ができます。コマンド操作（例：npx -y spacesheep@latest deploy ./dist）でも公開できます。

  • はじめてでも使えますか？

    Product Huntの案内では「It's free to start（はじめは無料）」とされています。

まとめ

  • SpacesheepはAIの出力を共有ページ「スペース」に変えるサービスです。
  • スペースはドキュメント、ダッシュボード、モックアップ、アプリのように扱えます。コメントや共同編集、全版の保存ができます。
  • Google DriveやGitHubと同期できます。電子署名機能も備わっていますが、署名は当事者が行う設計です。
  • 公開はChrome拡張やCLI、MCPプラグイン経由で行えます。非対話環境では長期キー（ss_…）で接続できます。
  • まずは無料で始められる点を踏まえ、資料共有やコンテンツ管理の運用に組み込むという使い方が考えられます。
